# 写作与内容规范

这份文档说明「内容放在哪、frontmatter 怎么写、Markdown 支持什么」。日常写作只看这一篇就够了。

---

## 1. 内容放哪里

`src/content/` 下按内容类型分成五块：

| 想写什么 | 放哪里 | 呈现为 |
| --- | --- | --- |
| 随笔、教程、单篇技术笔记 | `src/content/blog/`（可建子目录） | 博客文章 |
| 成体系的学习笔记 | `src/content/notes/<note>/` | 笔记 + 侧边目录 |
| 书 / 动画 / 漫画 / 电影 / 游戏记录 | `src/content/recreation/<分类>/`（可建 index + 子目录） | 书影音 |
| 短文本、句子、随想 | `src/content/cards/` 或子目录 | 卡片墙 |
| 首页、关于 | `src/content/pages/home.md`、`src/content/pages/about.md` | 独立页面 |

> 一篇内容只放在一个地方。书影音不再写在博客里，博客也不再需要 `review` 字段。

### 1.1 首页与关于

首页的正文、照片和“最近”文案都在 `home.md` 里，昵称和头像在 `src/site.config.ts` 里。

```yaml
---
title: 首页
description: ''
status: ''                 # 首页名字旁边的小状态，可留空
sections: [stats, notes, posts, cards, shelf]  # 想隐藏哪个区块就删掉
photos:
  - src: /images/home/window.jpg
    alt: 窗边的光
    caption: 窗
---
```

```markdown
这里放一些文字。

- 最近：啥也没做
- [GitHub](https://github.com/xxx) · [RSS](/rss.xml)
```

- `photos` 的图片放在 `public/images/home/`，路径写根路径；
- 头像在 `site.config.ts` 的 `avatar`，可以写 `/images/home/me.jpg`；
- 关于页只有 `title`、`description` 和正文；
- 各列表页的标题和“共 N 篇”文案在 `site.config.ts` 的 `copy` 里。

## 2. 文件命名与 URL

- 博客：`src/content/blog/<slug>.md` 或 `src/content/blog/<分组>/<slug>.md`，URL 对应 `/blog/<slug>/` 或 `/blog/<分组>/<slug>/`。
- 博客分组页：`/blog/groups/<分组>/`，由子目录自动生成。
- 笔记：`src/content/notes/<note>/index.md`，URL 是 `/notes/<note>/`。
- 笔记章节：`src/content/notes/<note>/<序号>-<slug>.md`，URL 是 `/notes/<note>/<slug>/`（数字前缀只用于排序，不进 URL）。
- 书影音：`src/content/recreation/<分类>/<slug>.md`，URL 是 `/shelf/<分类>/<slug>/`；分类页有 `/shelf/<分类>/book/` 书籍视图。
- 卡片：`src/content/cards/<slug>.md` 或 `src/content/cards/<分组>/<slug>.md`，URL 是 `/cards/<路径>/`。
- 首页：`/`，内容来自 `src/content/pages/home.md`。
- 关于：`/about/`，内容来自 `src/content/pages/about.md`。
- 文件名建议用英文小写和连字符：`dart-async.md`、`01-basics.md`。
- **标题写在 frontmatter 里**，文件名只决定 URL。
- 中文标题没问题；但文件名用中文会让 URL 变成百分号编码，不美观，也不方便分享。

## 3. 博客

### 3.1 最小写法

```markdown
---
title: 文章标题
date: 2026-11-11
---

正文从这里开始。
```

### 3.2 完整字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | string | ✅ | 文章标题 |
| `date` | date | ✅ | 发布日期，写成 `2026-11-11` |
| `description` | string | | 摘要，用于列表、搜索、RSS、SEO |
| `updated` | date | | 最后更新日期 |
| `tags` | string[] | | 标签，会生成标签页 |
| `featured` | boolean | | 是否置顶（列表顶部） |
| `cover` | string | | 封面图路径 |
| `draft` | boolean | | 草稿（默认不显示） |

### 3.3 正文约定

- **不要再写一遍 H1**。标题已经由 frontmatter 提供，正文从段落或 H2 开始。
- H2/H3 会自动进入右侧目录；没有 H2/H3 的文章不显示目录。
- 标准 Markdown + GFM（表格、脚注、任务列表、删除线）都支持。

### 3.4 文件夹分组

把文章放进 `blog/` 的子目录，子目录名就是分组：

```
src/content/blog/
├── tech/
│   ├── dart-async.md      → /blog/tech/dart-async/
│   └── math-squeeze.md
├── life/
│   └── hello-world.md     → /blog/life/hello-world/
└── draft-example.md       → 未分组，/blog/draft-example/
```

- 博客首页会出现分组标签；
- `/blog/groups/` 是分组总览，`/blog/groups/tech/` 是分组页；
- 分组可以嵌套，例如 `blog/tech/dart/foo.md`，URL 会保留完整路径。

## 4. 笔记

### 4.1 多文件笔记（支持任意层级）

```
src/content/notes/
├── dart-notes/
│   ├── index.md
│   ├── 01-basics.md
│   ├── 02-classes.md
│   └── 03-async.md
└── 示例笔记/
    ├── index.md
    └── 基础篇/              # 没有 index.md，只是分组
        └── 01-数学分析/
            └── index.md              # 有 index.md，是这一层的入口
```

规则：

- **每个有 `index.md` 的目录都是一个入口页**，URL 是 `/notes/<目录路径>/`；
- 顶层笔记目录必须有 `index.md`；
- 子目录可以没有 `index.md`，这时它只作为侧边栏里的分组标题，不生成页面；
- 给了子目录 `index.md`，它就会变成可点击的入口，并拥有自己的侧边栏；
- 目录下非 `index.md` 的 `.md` 是章节文件，URL 是 `/notes/<目录路径>/<文件名去掉数字前缀>/`；
- 目录名和中文会保留在 URL 里，章节文件的数字前缀不会进 URL。

`index.md`：

```markdown
---
title: Dart 语言笔记
description: 从语法到异步，边学边整理的 Dart 速查。
status: reading
tags: [Dart, Flutter]
---

笔记前言写在这里。
```

章节文件：

```markdown
---
title: 变量、类型与空安全
---

章节正文。
```

| 笔记字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | string | 这一层的标题；不写就用目录名 |
| `description` | string | 一句话介绍 |
| `status` | string | 笔记状态；可以是任意字符串，常用 `reading` / `finished` / `planned` / `paused` / `todo` / `doing` / `done` |
| `tags` | string[] | 标签 |
| `cover` | string | 封面图（可选，不放就用渐变色块） |
| `mode` | `auto` / `single` / `chapters` | 现在自动判断，保留兼容，一般不用写 |
| `draft` | boolean | 整个目录作为草稿 |

侧边栏默认展开 **2 层子目录**，但可以继续点开更深的分组；当前页面所在的目录会自动展开。更深的目录如果有 `index.md`，点进去后会以它为根重新打开侧边栏。想改变默认展开层数，改 `src/lib/content.ts` 里的 `NOTE_SIDEBAR_DEPTH`。

章节页右侧会显示本页 H2/H3 目录（和博客一致）；侧边栏负责文件树，右侧负责当前文件内部的小节。

同一本书里的相对链接可以直接写 Markdown 链接：

```markdown
[第一节](./1.1 实数的无尽小数表示与顺序.md)
```

构建时会自动转成站内 URL，路径里有空格也可以。

排序规则：笔记列表按顶层标题拼音首字母（A–Z）；同一目录下章节按文件名数字前缀（`01-`）排序，同序号按标题排序；子目录同样优先按目录名数字前缀排序。不需要手动写 `order`。

### 4.2 单文件笔记（适合旧的长笔记）

目录里只放一个 `index.md`：

```
src/content/notes/vim-notes/index.md
```

正文里的 H2/H3 会自动变成左侧目录，点击锚点跳转。适合一个文件写到底的速查、课程笔记。

`mode: single` 现在会自动判断，保留字段只是为了兼容旧文件。

### 4.3 多文件、单文件与嵌套怎么选

- 内容会持续变长、需要分章 → 多文件；
- 已经有几千字的长文件、想原样搬进来 → 单文件；
- 想把一门课拆成「基础篇 / 进阶篇 / 数学分析 / 高等代数」→ 用嵌套目录；
- 单文件以后想拆章，把 `index.md` 的内容按 H2 拆到 `01-xxx.md`，删掉 `mode: single` 即可。

## 5. 书影音

书影音不再写在博客里，而是独立放在 `src/content/recreation/` 下。**目录的第一段就是分类**，分类下面可以继续建文件夹分组：

```
src/content/recreation/
├── books/
│   └── one-hundred-years.md
├── anime/
│   ├── index.md              # 分类介绍，不是一条记录
│   ├── 01-神作/              # 文件夹分组，显示为「神作」
│   │   └── 某部动画.md       # 条目
│   └── 02-佳作/
│       └── 另一部动画.md
└── manga/
    └── frieren.md
```

- `分类/index.md` 是分类介绍，会渲染在分类页顶部，不会被当成一条书影音；
- 子文件夹就是分组，文件夹名的数字前缀只用于排序，显示时会去掉；
- 子文件夹里也可以放 `index.md` 作为分组介绍；
- 没有子文件夹的分类仍然按首字母 A–Z 分组，兼容原来的扁平写法。

每个分类下的条目：

```markdown
---
title: 《进击的巨人》：自由与代价
description: 一部从“把巨人赶出去”开始，最后把问题抛回给每个观众的作品。
date: 2026-09-18
creator: 谏山创
rating: 4.5           # 1–5，可带 .5
status: done          # 可以是任意字符串
tags: [观后感, 动画]
link: https://example.com   # 可选
---

正文从这里开始。
```

- 详情页 URL：`/shelf/<分类>/<分组>/<slug>/`，没有分组时是 `/shelf/<分类>/<slug>/`；
- 分类页 URL：`/shelf/<分类>/`；
- 分类页支持两种视图：**卡片视图**（文件夹分组，组内按首字母）和**书籍视图**（`/shelf/<分类>/book/`，连续阅读所有条目）；
- `status` 现在可以是任意字符串，`done` / `doing` / `planned` 等只是推荐值；
- 新增分类只需要新建目录，例如 `recreation/film/`；如果想给它一个中文名和封面颜色，在 `src/lib/recreation.ts` 的 `CATEGORY_META` 里加一条；
- `rating` 用 5 分制，显示为星星；
- 书影音的正文就是详情页正文，不需要另写一份。

## 6. 卡片

卡片是短文本集合，适合句子、随想、一条观察。

直接放文件：

```
src/content/cards/2026-11-12-first-snow.md
```

或者用子目录分组：

```
src/content/cards/reading/2026-11-05-margin.md
```

frontmatter 最小写法：

```markdown
---
date: 2026-11-12
tags: [日常]
---

正文。
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | string | | 不写时取正文第一行 |
| `date` | date | | 可省略；有日期时按时间倒序 |
| `tags` | string[] | | 标签 |
| `draft` | boolean | | 草稿 |

- 首页和 `/cards/` 会用摘要显示卡片，点进去是完整内容；
- 子目录名会作为卡片左上角的分组标识（例如 `reading`）；
- 卡片也可以直接写一段话，不需要标题。

## 7. 草稿

```yaml
draft: true
```

- **默认在开发和生产中都不显示**，不进列表、路由、搜索、RSS、sitemap；
- 想在本地预览草稿，启动时加环境变量：
  - PowerShell：`$env:SHOW_DRAFTS='1'; npm run dev`
  - bash：`SHOW_DRAFTS=1 npm run dev`
- 生产构建（`npm run build`）始终忽略这个开关，草稿不会被发布；
- **但文件仍然在仓库里**。如果仓库公开，别人可以直接看到。真正的私密内容请放在私有仓，不要放进公开仓。

## 8. Markdown 支持

### 8.1 数学

行内：`$E \subseteq \R^n$`；块级：

```markdown
$$
\lim_{n\to\infty} \frac{1}{n} = 0
$$
```

已经配置的宏：

| 宏 | 展开 |
| --- | --- |
| `\R` | `\mathbb{R}` |
| `\N` | `\mathbb{N}` |
| `\Z` | `\mathbb{Z}` |
| `\Q` | `\mathbb{Q}` |
| `\C` | `\mathbb{C}` |
| `\dd` | `\mathrm{d}` |
| `\abs{x}` | `\left|x\right|` |
| `\norm{x}` | `\left\|x\right\|` |

未知命令不会让构建失败（`throwOnError: false`），但会显示为普通文本。需要新宏时改 `astro.config.mjs` 的 `katexMacros`。

### 8.2 代码

````markdown
```dart
void main() => print('hello');
```
````

- 支持所有 Shiki 语言；
- 自动显示语言标签和「复制」按钮；
- 亮色/暗色两套主题。

### 8.3 表格与脚注

GFM 表格、`[^1]` 脚注、任务列表都可以直接用。

### 8.4 引用块

用引用块写定义或提示：

```markdown
> 写下来的东西不必完整，先让它有个地方待着。
```

会渲染成带左侧竖线的强调块。

### 8.5 图片

1. 把图片放到 `public/images/<文章或笔记>/xxx.png`；
2. Markdown 里写根路径：

```markdown
![截图](/images/dart/async.png)
```

根路径会自动处理，不需要手写仓库名前缀。

> 不要用 `./xxx.png` 这种相对路径——页面地址变化后会裂图。旧笔记里的相对图片需要手工搬到 `public/images/` 并改成根路径。

### 8.6 不要写 HTML 和 `<script>`

文章里尽量只用 Markdown。折叠块用 `:::toggle` 指令，剧透用 `||...||`，不要直接写 `<script>` 或大段 HTML。

### 8.7 分隔线

```markdown
上面一段。

---

下面一段。
```

`---` 会变成一条分隔线。注意：**它和上一段之间要空一行**；如果紧贴在文字下面，Markdown 会把它当成二级标题的下划线。

### 8.8 高亮与剧透

```markdown
这是 ==高亮== 文本。

这是 ||剧透|| 文本，鼠标移上去才显示。
```

- `==高亮==` 渲染为 `<mark>`；
- `||剧透||` 默认是黑色方块，悬停或键盘聚焦时显示，移开恢复；
- 只处理纯文本，不要在中间再套加粗、链接或代码。

### 8.9 Notion 风格折叠块

```markdown
:::toggle[点开看看]
这里是 **Markdown**，可以放段落、列表、代码。

- 第一项
- 第二项
:::
```

- 方括号里是标题，可以包含 `$公式$`、`**加粗**` 等行内 Markdown；
- 默认收起，写 `:::toggle[标题]{open}` 可以默认展开；
- 内容支持普通 Markdown；
- 不要在这个块里再嵌套另一个 `:::toggle`。

## 9. 导入旧笔记

假设要把 `C:\path\to\old-note.md` 导入成一篇笔记：

```bash
# 1. 先预览，不写文件
npm run import:note -- "C:\path\to\old-note.md" vim-notes --title "Vim 常用操作" --dry-run

# 2. 确认没问题后写入
npm run import:note -- "C:\path\to\old-note.md" vim-notes --title "Vim 常用操作"
```

脚本会：

- 补 frontmatter（`title`、`description`、`status`、`tags`、`mode: single`）；
- 把正文第一个 H1 提升为 `title` 并删除；
- 去掉 `[toc]` 占位；
- 写入 `src/content/notes/vim-notes/index.md`，默认不覆盖已有文件（`--force` 可覆盖）。

导入后需要手工处理的：

1. 相对图片路径；
2. 不认识的 LaTeX 宏；
3. 章节标题层级（如果 H3 起步，目录仍然能生成，只是层级看起来会平）；
4. 过于私人的内容。

## 10. 常见问题

**Q：改完文件页面没变化？**
开发模式下 Astro 会热更新；如果改的是 `src/content.config.ts`，需要重启 dev server。

**Q：新增文件会被自动检测吗？**
会。`npm run dev` / bat / exe 启动的 dev server 会监听内容目录，新增 Markdown 后几秒内出现，不需要重启。

**Q：新增标签后标签页 404？**
标签页只为博客生成；书影音、卡片的标签目前只作为展示，不生成标签页。确认博客标签写在 `tags` 里。

**Q：重命名章节后链接失效？**
URL 来自文件名（去掉数字前缀），重命名会改变 URL。可以用相对 Markdown 链接让构建自动解析，也可以写完整的 `/notes/.../` 路径。

**Q：构建报“笔记缺少 index.md”？**
只有**顶层笔记目录**必须有 `index.md`；嵌套子目录可以没有，作为纯分组。

**Q：构建报“声明了 mode: single，但还有章节文件”？**
这个检查已经取消，`mode` 现在自动判断，旧字段会被忽略。

**Q：书影音分类不显示？**
分类下至少要有一条非 `index.md` 的记录；分类介绍 `index.md` 本身不算条目。中文名可以在 `src/lib/recreation.ts` 的 `CATEGORY_META` 中配置。

**Q：日期格式？**
`date: 2026-11-11`，不要加引号；带时间也可以写 `2026-11-11T20:00:00+08:00`。

**Q：子目录不显示，或者侧边栏里点不动？**
- 顶层笔记必须有 `index.md`；
- 子目录有 `index.md` 会变成可点击入口；没有 index 的子目录也可以展开，只是没有自己的介绍页；
- 侧边栏默认展开 2 层，可以继续点开更深的分组；想改变默认层数改 `src/lib/content.ts` 的 `NOTE_SIDEBAR_DEPTH`。

**Q：嵌套目录的 URL 是什么？**
目录名原样保留，例如 `示例笔记/基础篇/01-数学分析/`；章节文件的数字前缀会去掉，例如 `01-basics.md` → `basics/`。

**Q：能不能用 `.mdx`？**
博客、笔记、书影音、卡片都支持 `.mdx`，但普通内容建议用 `.md`；首页和关于页现在也是普通 Markdown，不再需要 MDX。

**Q：头像和照片怎么换？**
头像改 `src/site.config.ts` 的 `avatar`；照片放到 `public/images/home/`，再改 `src/content/pages/home.md` 的 `photos`。照片留空数组就不会显示照片墙。

**Q：首页/列表页的文字在哪改？**
首页正文和关于页在 `src/content/pages/`；昵称、头像、导航、列表页标题和“共 N 篇”在 `src/site.config.ts`。

### 12.2 导出笔记

单页：打开任意笔记，点正文上方的「打印 / 保存 PDF」，在浏览器打印窗口里选择“另存为 PDF”。打印样式会隐藏顶栏、侧边栏、本页目录和按钮，并展开所有折叠块。

批量：

```bash
npm run export:notes
```

脚本会：

1. 运行 `npm run build`；
2. 启动一个临时 preview 服务；
3. 把 `dist/notes` 下每个笔记页面打印成 PDF；
4. 保存到 `exports/notes-pdf/`；
5. 打包成 `exports/notes-export-*.zip`；
6. 关闭临时服务。

如果已经有服务在运行，也可以：

```bash
npm run export:notes -- http://127.0.0.1:4322
```

`exports/` 已加入 `.gitignore`，不会提交到仓库。

> 导出的是渲染后的页面。笔记里如果引用了教材原文、课件图片或付费内容，PDF 仍然包含这些内容；不要把导出包公开发布。
